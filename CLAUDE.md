# Project notes

- UI language is Korean (no i18n framework; strings are inline). Keep new UI text, validation messages and toasts in Korean. `html lang="ko"`, font is Pretendard via next/font/local.

- Internal LAN app: Next.js 16 App Router + SQLite (better-sqlite3 + Drizzle) + shadcn/ui. Light theme only; never add `.dark` styles or theme toggles.
- Auth is homegrown cookie sessions. `src/proxy.ts` does the cookie-only redirect; `requireUser()` in `src/lib/auth/dal.ts` does the DB-backed check. New pages go under `src/app/(app)/` so they are guarded. Only `/login` is public. The proxy must never redirect *away* from `/login` based on the cookie alone; that caused a redirect loop with stale cookies. The login page does the DB-backed check.
- Call `requireUser()` in every server action that touches data.
- DB access is synchronous (better-sqlite3): use `.get()` / `.all()` / `.run()`, not `await`.
- Schema changes: edit `src/lib/db/schema.ts`, then `pnpm db:generate`. Migrations auto-apply on app startup.
- Use `pnpm`. `pnpm db:seed` creates the admin user from `.env`.
- Team member records live in `members` (separate from login `users`). Mutations go through server actions in `src/lib/members/actions.ts`, which call `requireAdmin()`. Validation is zod in `src/lib/members/schema.ts`.
- Dialog forms mount their inner form only while open so `useActionState` resets each time (see `member-dialog.tsx`).
- `NativeSelect` from `components/ui/native-select` *is* the `<select>`; pass `id/name/defaultValue` to it directly and put `NativeSelectOption` children inside. Never nest a raw `<select>` in it (renders invisible).
- If a server action's success swaps the client form for a different component in the same commit, handle success inside the action wrapper (see `withDone` in `users/account-dialog.tsx`), not in a `useEffect` of the form.
- SQLite FK caveat: drizzle-kit drops `ON DELETE …` when generating `ALTER TABLE … ADD COLUMN … REFERENCES`. Check generated SQL for FK columns added to existing tables; fix with a `drizzle-kit generate --custom` table rebuild (see `drizzle/0003_*`). The `sqlite3` CLI has foreign keys OFF by default: prefix manual deletes with `PRAGMA foreign_keys=ON;`.
- Dates: all keys are `YYYY-MM-DD` strings in Asia/Seoul via `src/lib/dates.ts`; working-day logic lives in `src/lib/workdays.ts` (Mon–Fri minus `holidays` rows). Week key = Monday.
- Delete flows: server actions return `{ ok, error }` and never throw to the client; client wraps the call in try/catch and toasts.
- Team leader = `members.is_leader`, one per team, set via `setTeamLeader` (admin only). It is display-only for now; if leaders get permissions later, check `isLeader` + same `team` in the server action.
- `Tooltip` needs the `TooltipProvider` that lives in the root layout.
- Dashboard week view is a generic timeline: build `TimelineItem[]` (start/end keys clipped to the week, label, member colour from `memberColorMap`) and pass to `WeekTimeline`. Add team schedules by pushing more items in `week-leaves.tsx` (or a sibling), not by adding rows/columns.
- Member colours are per member (`MEMBER_PALETTE`, by id rank); leave *type* colours (`LEAVE_BADGE_CLASS`) are used on the monthly calendar and status badges. Keep that distinction unless the user asks to unify.
- Keep the dashboard minimal (daily forms + week timeline + buttons). New team-level views get their own page under `src/app/(app)/` plus a nav entry in `main-nav.tsx`, not another dashboard section.
- Milestones: Gantt in `src/app/(app)/milestones/gantt.tsx` is a server component; bar geometry is percentage of the visible day range. Detail is URL-driven (`?m=ID`) and server-rendered inside a thin client `DetailDialog`; server actions revalidate `/milestones` so the open dialog refreshes. Permissions live in `milestoneAccess()`; always call it in actions, never trust the client.
- Posting a milestone 현황 update is the normal way status/progress change; `updateMilestone` also logs an update row when status/progress differ.
- Demo data: `scripts/seed-mock.ts` (`pnpm db:seed:mock`, `--reset`, `--clean`). It identifies its own rows by the MOCK_* name lists, so keep those lists in sync if you add mock entities. Scripts must not import modules that import `server-only` (e.g. `workdays.ts`); reimplement small helpers instead.
- Daily plan = `daily_tasks` rows (title/status/note/position); `daily_logs.plan` is legacy and no longer written, `daily_logs.done` holds free-text extras. Team/logs pages render both via `components/task-lines.tsx`. Task actions check ownership through `requireMember()` + memberId match.
- Client components must not import runtime values from `src/lib/db/schema.ts` (type-only imports are fine). Enum constants (`TASK_STATUSES`, `MILESTONE_STATUSES`, `LEAVE_TYPES`) live in `lib/*/types.ts`; schema imports them, not the other way round. Importing the schema into client code pulls drizzle into the browser bundle and broke under HMR.
- Leader reviews: `daily_reviews` + `reviewerContext()` in `lib/reviews/queries.ts` (admin all; leader = own team, not self; member = own only). Always filter with `canSee` before rendering reviews and check `canReview` in the action. `daily_tasks.note` column is unused by the UI now (per-task memo was removed by request); leave it alone.
- IA (phase 1 of the restructure): 4 nav areas 내 업무 `/my/*`, 팀 `/team*`, 일정 `/schedule`, 관리 `/admin/*` (admin only; layout redirects others). Each area has a `SubNav` tab bar; page headings inside areas are `h2`. New pages go under the matching area and get a tab, not a top-level nav item. Old paths keep redirect stubs.
- Teams are rows in `teams` (`leader_member_id`). Never read `members.team` / `members.is_leader` (columns removed). Use `allMembers()`/`memberById()` (`Member` type from `lib/members/types.ts`, includes `team` + `isLeader`) and `milestonesInRange()`/`milestoneById()` (`MilestoneRow`). Team leader is set in 관리 → 팀.
- SQLite migration style used for 0008: `ADD COLUMN` + data `UPDATE` + `DROP COLUMN` (SQLite ≥ 3.35), never a table rebuild while foreign keys are on (implicit DELETE cascades). drizzle-kit `generate` needs a TTY for rename prompts; use `generate --custom` and write the SQL by hand, keeping the snapshot in sync with the schema file.
- Phase 2 (연결): `weekly_items` (status, milestoneId, monthlyGoalId, assignedBy) and `monthly_goals` (status, milestoneId); `daily_tasks.weekly_item_id` links a day item to a week item. Actions in `lib/plans/actions.ts` (owner-only via `requireMember`), queries in `lib/plans/queries.ts`. `pullWeeklyItemToDay` creates the linked daily task and bumps the week item to in_progress. Status enums reuse `TASK_STATUSES`.
- drizzle-kit: `generate --custom` does NOT refresh the snapshot. After hand-written migrations, run a real `generate` with prompts auto-answered (`printf '\r'` through `script`) and replace its SQL with `SELECT 1;` (see `drizzle/0010_snapshot_sync.sql`), then confirm `generate` reports "No schema changes".
- Phase 3 (팀장 관리): `/team/manage` (leaders/admin; tab shown conditionally in `team/layout.tsx`). Insights and attention rules live in `lib/team/insights.ts` — add new rules there, not in the page. Leader actions on a teammate go through `managerOf()` in `lib/plans/actions.ts` (admin or that team's leader, never self).
- Weekly team report: `team_reports` (one per team/week, draft|final). Generation = `collectWeekSource()` → `renderSource()` → `chatCompletion()` (OpenAI, fetch only, no SDK) → upsert. Permissions via `reportAccess()` (admin all; leader own team edit; member read final only). Never log the API key or the full prompt; errors are mapped to Korean messages in `openai.ts`. To test without a real key, point `OPENAI_BASE_URL` at the mock server in the scratchpad e2e folder.
- Leave requests: types/costs live in `lib/leaves/types.ts` (change 조퇴/반차 rules there, both form and actions read them). `createLeaveRequest` is the only way members add leave; it writes `leave_requests` + `leaves` (request_id) in one transaction. The print page under `src/app/print/` is outside the `(app)` layout on purpose (no chrome) but still behind `requireUser`. Keep table `<colgroup>` widths in sync with the DOCX grid (dxa values in comments) if the company changes the form.
- zsh note: quote paths containing `[id]` in shell commands (glob) — an unquoted `mkdir src/app/x/[id]` silently fails.
- Members have both `position` (직책, required) and `rank` (직급, optional) plus `phone`. Printed 휴가 품의서 uses `rank || position` for the 직위 cell (snapshotted into `leave_requests.position`).
- Leave balance: rules in `lib/leaves/policy.ts` (pure, client-safe: leave year from join date, default annual by year of service with first-year monthly accrual), aggregation in `lib/leaves/balance.ts` (server). `members.annual_override` overrides the default; `total_offdays` is legacy and must not be read. Form preview, admin table and `createLeaveRequest` all go through `leaveBalance()`.
- AI documents: `components/ai-doc/ai-doc-editor.tsx` is the generic editor (pass bound server actions via inline `"use server"` closures from the page). Meeting notes (`lib/meetings/*`) reuse `collectWeekSource()` from reports for both last and this week plus `buildInsights()` flags. Keep the report's `report-editor.tsx` or migrate it to the generic editor when touching it next.
- Dashboard week timeline shows leaves only (user asked to keep the first page simple). Milestone views: Gantt + month calendar under `/team/milestones` (`?view=calendar`). `packLanes` from `components/week-timeline.tsx` is shared for bar packing.
- Login identifier is `users.email` (falls back to `users.username` for legacy rows). New member accounts: `username = email = members.email`, admin supplies only the initial password (`linkAccount` new mode). Editing a member's email updates the linked user's email. UI shows `user.email ?? @username`.
